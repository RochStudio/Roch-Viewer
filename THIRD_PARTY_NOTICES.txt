Third-party components
======================

inpoutx64.dll  (NOT distributed with this project)
------------------------------------------------------------------
Roch Viewer needs a low-level access driver to read physical memory, PCI
configuration space and I/O ports. It uses inpout32/64 by Highresolution
Enterprises (www.highrez.co.uk), which reports:

  Copyright (c) 2008 Highresolution Enterprises.
  Portions Copyright (c) Logix4u.

That file is deliberately NOT included in this repository or in any build
produced from it. It is a third-party binary under its own terms, and this
project is GPL-3.0; shipping it alongside would make the combined work
something neither licence covers. Obtain it from the vendor and place it
beside the executable yourself -- see "Prerequisites" in README.md.

It carries the kernel driver inside itself as a resource and installs it as a
Windows service on the first elevated run, so the DLL is the only file needed
and the service outlives this program.

ZenStates-Core and ZenTimings  (followed, not bundled)
-------------------------------------------------------
Copyright (c) irusanov -- https://github.com/irusanov
GPL-3.0.

The AMD backend follows that work. Register numbers, bit fields and the bounds
applied to decoded values were taken from or checked against ZenStates-Core and
ZenTimings; the modules that do so carry a notice saying which, and the
comments beside the definitions say what came from where.

No source file from either project is included here. This project is
distributed under GPL-3.0, the same licence they use, which is what makes
building on them permitted -- and it is why the licence is GPL-3.0 rather than
something more permissive. Copyright in the parts that derive from that work
remains with its authors.

The files concerned:

  crates/rochviewer/src/amd/agesa.rs
  crates/rochviewer/src/amd/apob.rs
  crates/rochviewer/src/amd/fch_smbus.rs
  crates/rochviewer/src/amd/power_metrics.rs
  crates/rochviewer/src/amd/profile/
  crates/rochviewer/src/amd/smu_clocks.rs
  crates/rochviewer/src/amd/smu_power.rs
  crates/rochviewer/src/amd/smu_voltages.rs
  crates/rochviewer/src/amd/timings.rs
  crates/rochviewer/src/memory/ddr5_pmic.rs
  crates/rochviewer/src/memory/ddr5_telemetry.rs

Three other places mention those projects without following them, and carry
the plain notice instead: ddr5_spd.rs checks JESD400-5 offsets against them,
dimm_inventory.rs borrows a label format, and the window a visual convention.

The MIT-licensed gnr-smu research project by Zorko was consulted for
independent Granite Ridge RSMU mailbox-address provenance. No gnr-smu source
is bundled, and the diagnostics that used it are not in this repository.

Rust crates  (compiled in)
--------------------------
The executable is built from crates published on crates.io, each under a
licence compatible with GPL-3.0: eframe and egui (MIT OR Apache-2.0), windows
(MIT OR Apache-2.0), wmi (MIT OR Apache-2.0), libloading (ISC), regex, serde,
serde_json, image, png and arboard (MIT OR Apache-2.0), and winresource (MIT)
at build time, with their own dependencies. `cargo tree` lists the full set
for any build; each crate's licence text ships in its source package.

Fonts are not bundled: Consolas, Segoe UI Symbol and Segoe UI Emoji are read
from the Windows fonts folder at run time.

Reference tools
---------------
CPU-Z, HWiNFO, the reference timing tool, ASRock Timing Configurator and MemTweakIt were
used as reference instruments: their readings were compared against this
project's on the same machine at the same moment to confirm that a register
had been located correctly. No source, header or data file from any of them
is included here, and none of them is required to run this.

Where a register was established by comparing against one of those tools, or
by diffing full captures across a controlled BIOS change, the evidence is
recorded in a comment beside the definition.
